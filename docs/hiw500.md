# HIW-500

[HIW-500](https://bitrobot-foundation.github.io/humanoids-in-the-wild-500-hours/)
("Humanoids In-the-Wild", BitRobot Foundation, CC-BY-4.0) is whole-body
teleoperation of a Unitree G1 humanoid in 12 real homes: 500+ hours, 10+
household tasks, 161 subtask labels. It is published twice on Hugging Face, and
neither repository is gated:

- [`BitRobot/HIW-500`](https://huggingface.co/datasets/BitRobot/HIW-500): the
  raw ROS 2 bags in MCAP. `daft_physical_ai.datasets.hiw500` reads this one.
- [`BitRobot/HIW-500-LeRobot`](https://huggingface.co/datasets/BitRobot/HIW-500-LeRobot):
  a LeRobot v3.0 conversion. Daft reads it natively with
  `daft.datasets.lerobot.read()`. See [Raw or LeRobot](#raw-or-lerobot).

The reader works in stages, so you can bound the work before touching the
large episode files:

| Function | Reads |
| --- | --- |
| `raw()` | Object listing only: paths and sizes |
| `info()`, `subtasks()` | `info.json` (a few hundred bytes per episode) |
| `calibration()` | Camera calibration json/yaml (a few KB per episode) |
| `metadata()` | MCAP header, footer, and summary (range reads) |
| `messages()` | Raw ROS 2 CDR payloads for chosen topics and time window |
| `joint_states()`, `wbc_states()`, `annotations()` | Decoded state, controller, and annotation topics |
| `camera_frames()` | JPEG camera topics, decoded to images |
| `lerobot_subtask()` | Expression for the LeRobot release: active subtask per frame |

## Setup

```bash
pip install "daft-physical-ai[hiw500]"
```

The `hiw500` extra adds the `mcap` reader, `huggingface_hub` for the catalog
listing, and PyYAML for the head-camera calibration. No token is needed. If
`HF_TOKEN` is set or you ran `hf auth login`, the token is used for `hf://`
paths, which raises the Hub rate limits.

## Episode layout

```text
<Task-Name>/                              # e.g. Hang-Hanger, Setting-The-Table
`-- episode_<YYYY-MM-DD_HH-MM-SS>/        # recording session
    `-- episode_<NNNN>/                   # episode within the session
        |-- episode_<NNNN>.mcap
        |-- info.json
        `-- calibration/params/
            |-- camera_<serial>.json      # RealSense wrist cameras
            `-- head_camera_params.yaml   # head stereo pair
```

At revision `c35830b9fcccf444c0318560466d0e35c7285675` the repository has 10
task folders, 23,074 episodes, and 105,760 files, with 8.94 TB of MCAP (0.3 MB
to 4.8 GB per episode). Every episode has an MCAP and an `info.json`. 3,038
episodes have no wrist-camera json, 18,975 have `head_camera_params.yaml`, and
560 spell it `head_camera-params.yaml`; `raw()` picks up both spellings.

## Catalog: `raw()`

```python
from daft_physical_ai.datasets import hiw500

episodes = hiw500.raw(tasks="Hang-Hanger")
sample = episodes.sort("mcap_size").limit(4)
sample.select("episode_id", "session_time", "mcap_size").show()
```

`path` defaults to `hf://datasets/BitRobot/HIW-500`. Append `@<revision>` to
pin a commit. A local mirror or object-store root also works.

On Hugging Face, `raw()` lists the task folder names when called (one request,
skipped when you pass `tasks`). Each task's recursive file listing runs when the
plan executes, through the Hub's paginated tree API, and the tasks are listed
concurrently. Cataloging the full repository (23,074 episodes) took 14.7 s this
way, against 33 s listing the tasks one after another; one task takes 2 to 10 s.
Pass `tasks` so unselected tasks are never listed. Other stores use Daft's lazy
glob.

| Column | Description |
| --- | --- |
| `task` | Task folder name, e.g. `Hang-Hanger` |
| `session` | Session stamp, `YYYY-MM-DD_HH-MM-SS` |
| `session_time` | The session stamp as a naive timestamp (local wall-clock time) |
| `episode_number` | Episode number within the session |
| `episode_id` | `<task>/episode_<session>/episode_<NNNN>` |
| `episode_dir` | Episode directory |
| `mcap_path`, `mcap_size` | MCAP path and size in bytes |
| `info_path` | `info.json` path |
| `calibration_paths` | Sorted calibration json/yaml paths (may be empty) |
| `episode_mcap` | Lazy `daft.File` reference to the MCAP |

The session stamp is local time. For the episodes checked it is 8 hours ahead
of the UTC `start_timestamp_ns` in `info.json`. Use `info()` for exact times.

## Episode info and subtasks: `info()`, `subtasks()`

```python
details = hiw500.info(sample)
details.select("episode_id", "task_name", "scene", "duration_seconds", "subtask_count").show()

hiw500.subtasks(sample).select("episode_id", "label", "start_offset_seconds", "end_offset_seconds").show()
```

`info()` keeps the input columns and adds `episode_name`, `task_name` (natural
language, e.g. `hang hanger`), `scene`, `start_timestamp_ns`,
`end_timestamp_ns`, `duration_ns`, `duration_seconds`, `subtask_count`, and the
whole file as `info_json`. Timestamps are Unix nanoseconds on the MCAP
`log_time` clock.

`subtasks()` returns one row per subtask label. A label starts at its
`timestamp_ns` and lasts until the next label, or until the episode end for the
last one. `start_offset_seconds` and `end_offset_seconds` are relative to the
episode start. Some episodes have no labels (`subtask_count == 0`) and give no
rows.

The MCAP also records the labels: the `/annotation` topic holds the task text
at the episode start, then each subtask label at its start time.
`annotations()` decodes that topic. Use `subtasks()` unless you are already
reading the MCAP.

## Calibration: `calibration()`

```python
hiw500.calibration(sample).select("episode_id", "camera", "stream", "fx", "fy", "cx", "cy").show()
```

One row per camera stream, in long format:

| `camera` | `stream` | Source |
| --- | --- | --- |
| `left_wrist`, `right_wrist` | `color`, `ir1`, `ir2` | `camera_<serial>.json` (Intel RealSense) |
| `head` | `left`, `right` | `head_camera_params.yaml` (stereo calibration) |

Columns: episode identity, `source_path`, `camera`, `stream`, `serial_number`,
`width`, `height`, `fx`, `fy`, `cx`, `cy`, `distortion_model`,
`distortion_coeffs`, `extrinsics_reference`, `rotation` (9 values),
`translation` (3 values), and `params_json` (the whole source file as JSON).

Values are passed through as stored:

- Wrist `ir1` and `ir2` rows carry the json's `extrinsics_to_color`, so
  `extrinsics_reference` is `color`. These come from RealSense `rs2_extrinsics`,
  which stores the rotation column-major and the translation in metres.
- The head `right` row carries the yaml's stereo `R` and `T`, with
  `extrinsics_reference` `left`. `T` and `baseline` are about 60, which fits
  millimetres for this camera. The head distortion is the OpenCV 5-coefficient
  model, labelled `plumb_bob`.
- The yaml's rectification matrices (`R1`, `R2`, `P1`, `P2`, `Q`) and `E`/`F`
  are only in `params_json`.

The head image is the stereo pair side by side (1280x480), and the yaml's
`image_size` is per eye (640x480).

## Summaries: `metadata()`

```python
hiw500.metadata(sample).select("episode_id", "message_count", "message_start_time", "channels").show()
```

Range-reads the MCAP summary. Message payloads are not downloaded. Adds
`ros_distro` (`humble`), `message_count`, `message_start_time`,
`message_end_time`, `chunk_count`, `indexed`, `topics`, and `channels` (a list
of `{topic, schema_name, message_count}`). `info()` and `metadata()` can be
chained in either order.

## Topics and message encodings

Every MCAP uses the `ros2` profile. Every channel has `cdr` message encoding
with the full `ros2msg` schema text embedded. Rates below are from two
Hang-Hanger episodes.

| Topic | Schema | Rate | Decoded by |
| --- | --- | --- | --- |
| `/stamped/lowstate` | `homies/msg/LowStateStamped` | 100 Hz | `joint_states()` |
| `/wbc_lerobot` | `std_msgs/msg/String` (JSON) | 50 Hz | `wbc_states()` |
| `/annotation` | `std_msgs/msg/String` | per label | `annotations()` |
| `/camera/head/image/compressed` | `sensor_msgs/msg/CompressedImage` (JPEG) | 15-20 Hz | `camera_frames()` |
| `/camera/{left,right}_wrist/image/compressed` | `sensor_msgs/msg/CompressedImage` (JPEG) | 30 Hz | `camera_frames()` |
| `/camera/{left,right}_wrist/{ir1,ir2}/compressed` | `sensor_msgs/msg/CompressedImage` (JPEG, mono) | 30 Hz | `camera_frames()` |
| `/stamped/lowcmd` | `homies/msg/LowCmdStamped` | 100 Hz | raw bytes |
| `/stamped/secondary_imu` | `homies/msg/IMUStateStamped` | 100 Hz | raw bytes |
| `/stamped/dex1/{left,right}/state` | `homies/msg/MotorStateStamped` | 100 Hz | raw bytes |
| `/stamped/dex1/{left,right}/cmd` | `homies/msg/MotorCmdStamped` | 100 Hz | raw bytes |
| `/lf/odommodestate` | `unitree_go/msg/SportModeState` | 20 Hz | raw bytes |

The decoders are a small CDR reader for these fixed layouts. They were checked
against the reference `mcap-ros2-support` decoder on every LowState,
`/wbc_lerobot`, and head-camera message of a real episode, with no mismatches.
The reference decoder is not a dependency. It takes about 1.8 ms per LowState
message, so a full episode's joint states would take minutes. The other topics
stay raw CDR bytes in `messages()`. Their schema text is in each MCAP if you
want to decode them with `mcap-ros2-support`.

## Messages: `messages()`

```python
one = episodes.sort("mcap_size").limit(1)
start = hiw500.metadata(one).select("message_start_time").to_pydict()["message_start_time"][0]

rows = hiw500.messages(one, topics=["/stamped/dex1/left/state"], start_time=start, end_time=start + 2_000_000_000)
rows.select("episode_id", "topic", "log_time", "data").show()
```

`messages()` collects the catalog's MCAP paths, so filter and limit the catalog
first. Each file becomes a `daft.read_mcap` scan with the topic and time filters
pushed into the reader. `start_time` is inclusive and `end_time` exclusive, in
`log_time` units (Unix nanoseconds). The reads are ranged: a 1 s window of a
3.07 GB episode on Hugging Face takes about 6 s. Output: `source_path`, `topic`,
`log_time`, `publish_time`, `sequence` (all `int64`; rosbag2 leaves `sequence`
at 0), CDR `data` as binary, and `task`, `session`, `episode_number`,
`episode_id`.

The default topics are every non-camera topic, so a bare call never reads JPEG
payloads. `topics=None` reads everything. Topics run on their own clocks and are
not resampled or aligned.

## Joint states: `joint_states()`

```python
states = hiw500.joint_states(one, start_time=start, end_time=start + 2_000_000_000)
states.select("log_time", "stamp_ns", "q", "dq", "tau_est", "imu_rpy").show()
```

Decodes `/stamped/lowstate` into `stamp_ns` (message header), `tick`,
`mode_machine`, `q`, `dq`, `tau_est` (29 x float32, in `JOINT_NAMES` order),
and the pelvis IMU: `imu_quaternion` (w, x, y, z), `imu_gyroscope`,
`imu_accelerometer`, `imu_rpy`. `JOINT_NAMES` is the G1 motor order, the first
29 of LowState's 35 motor slots, and the order of the LeRobot release's
`observation.state`. Malformed payloads give nulls.

Some episodes have joint positions that do not change at all. The smallest
Hang-Hanger episode (`episode_2026-05-25_08-18-22/episode_0001`, 47 s, no
subtask labels) has bit-identical `q` for all 4,670 messages while `tau_est`
and the IMU vary. Check for this before training on an episode.

## Whole-body controller: `wbc_states()`

```python
hiw500.wbc_states(one, start_time=start, end_time=start + 2_000_000_000).show()
```

`/wbc_lerobot` is JSON in a `std_msgs/String`. `wbc_states()` returns `pivot`
(vx, vy, vyaw, roll, pitch, yaw, height), `ee_state` and `ee_action` (12
values each: left then right x, y, z, roll, pitch, yaw), and `left_trigger`,
`left_squeeze`, `right_trigger`, `right_squeeze`. This is the source of the
LeRobot release's 23-value vectors: `observation.state.wbc` is `pivot` +
`ee_state` + the four gripper values, and `action` is `pivot` + `ee_action` +
the four gripper values (checked on LeRobot episode 0, frame 0: equal to
float32 precision).

## Camera frames: `camera_frames()`

```python
frames = hiw500.camera_frames(
    one,
    cameras=["head", "left_wrist"],
    start_time=start,
    end_time=start + 1_000_000_000,
    width=224,
    height=224,
)
frames.select("episode_id", "camera", "log_time", "stamp_ns", "width", "height", "data").show()
```

| Alias | Topic |
| --- | --- |
| `head` | `/camera/head/image/compressed` (1280x480, stereo side by side) |
| `left_wrist`, `right_wrist` | `/camera/{side}_wrist/image/compressed` (640x480 RGB) |
| `left_wrist_ir1`, `left_wrist_ir2`, `right_wrist_ir1`, `right_wrist_ir2` | `/camera/{side}_wrist/{ir1,ir2}/compressed` (640x480 mono) |

Each message is one JPEG, so frames decode independently with Daft's native
image decoder. Unlike ABC-130k's video streams, there is no keyframe warm-up and
a window late in an episode decodes only its own frames. `mode` sets the image
mode for every selected camera (default `RGB`; `L` keeps IR single-channel).
Output: episode identity, `camera`, `topic`, `log_time`, `publish_time`,
`sequence`, `stamp_ns` (capture time from the header), `frame_id`, `format`,
`width`, `height`, and image `data`.

## Raw or LeRobot

The LeRobot release (`BitRobot/HIW-500-LeRobot`, revision `2d32431`) has
23,743 episodes and 40.8M frames at 30 fps. Daft reads it directly:

```python
from daft.datasets import lerobot

frames = lerobot.read(hiw500.LEROBOT_REPO)
frames = frames.with_column("subtask", hiw500.lerobot_subtask())
```

How the two releases relate, from checking both:

- Episodes. Per-task episode counts are equal for 8 of the 10 raw tasks. The
  raw release has 8 more Kitchen-Organization and 83 more Restocking-Fridge
  episodes. The LeRobot release adds 760 "building children table" episodes,
  which come from BitRobot's separate
  [assembly challenge dataset](https://huggingface.co/datasets/BitRobot/2026-humanoid-ikea-assembly-challenge)
  and are not in `BitRobot/HIW-500`.
- No shared key. LeRobot episode metadata has no raw path or session stamp,
  and LeRobot episode order is not the raw path order. LeRobot episode 0 is raw
  `Clean-Up-The-Room/episode_2026-02-25_10-16-03/episode_0001`: same duration
  (575.5 s), the same subtask sequence shifted by 36 ms, and
  `observation.state` at frame 0 exactly equals the raw LowState `q` (all 29
  joints) of the message 37 ms after `info.json`'s start. LeRobot episode 1 is not
  the next raw episode. To pair episodes, match on task, duration, and subtask
  sequence.
- State. `observation.state` is the 29 joint positions (`q` here).
  `observation.state.wbc` and `action` come from `/wbc_lerobot` (see
  [`wbc_states()`](#whole-body-controller-wbc_states)).
- Cameras. LeRobot has `head`, `left_wrist`, and `right_wrist` as AV1 video at
  30 fps; the raw head JPEGs arrive at 15-20 Hz. The raw IR streams are not in
  the LeRobot release.
- Not in LeRobot: wrist IR images, gripper motor state and commands
  (`/stamped/dex1/*`), low-level motor commands (`/stamped/lowcmd`), joint
  velocities and torques, the secondary IMU, odometry, camera calibration, and
  the original message timestamps.
- Language. `language_persistent` repeats the episode's whole subtask list on
  every frame (`style == "subtask"`, `timestamp` in seconds from the episode
  start, first entry is the task text at 0). `language_events` is empty.
  `lerobot_subtask()` picks the latest entry at or before each frame's
  `timestamp`, which gives the active label per frame. For episode-level labels,
  take frame 0 and explode `language_persistent`.

Use the LeRobot release to train policies on synchronized 30 fps
state/action/video, or when you want the 760 assembly episodes. Use the raw
release when you need anything in the "not in LeRobot" list, exact sensor
timing, calibration, or per-stream rates above 30 Hz (joint state at 100 Hz).

Note: with Daft v0.7.20, a `where` on one `episode_index` after `lerobot.read()`
did not prune data files and was still running after 10 minutes. To look at a
few episodes,
read the relevant `data/chunk-*/file-*.parquet` directly with
`daft.read_parquet`, using `meta/episodes` to find the file.

## Recommended order

1. Pass `tasks` to `raw()`.
2. Pick a bounded sample by `mcap_size`, then use `info()` to keep episodes
   with subtask labels.
3. Call `metadata()` when you need topics, counts, or time bounds.
4. Pass explicit topics and time windows to `messages()` and the decoders.
5. Decode cameras last, with a time window.

See [`examples/hiw500_episode_messages.py`](../examples/hiw500_episode_messages.py)
for a runnable script.
